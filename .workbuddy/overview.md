# 轻账本 v1.1 增量交付总览（2026-09-09）

## 本次做了什么
用户三点诉求，经团队标准 SOP（PM 许清楚 → 架构师高见远 → 工程师寇豆码 → QA 严过关，两轮测试）全部交付：

1. **删除「意见反馈」入口**：我的页、关于页两处入口移除，6 个废弃字符串资源键（ledger_soon / mine_backup_soon / mine_remind_soon / mine_feedback / about_feedback / feedback_email）全工程清理至零残留。
2. **修复「导出数据显示失败」**：根因是导出链路把「用户取消」和「真实失败」一律静默吞掉，用户无感知或只看到笼统失败。现改为三态语义（saved / cancelled / failed），失败按临时文件写入 / 保存面板 / 拷贝三个环节分别留日志；picker 参数修正为 `['.csv']`；成功提示带导出条数，取消保持静默。
3. **三个「即将上线」假入口全部转真**：
   - **多账本**：新增账本管理页（创建/重命名含图标颜色/删除）+ 首页 bindSheet 切换弹层；数据按 ledger_id 全链路隔离，当前账本持久化、冷启动恢复；有流水的账本拦截删除，无流水账本删除需「不可撤销」二次确认并在事务内级联清理。
   - **备份与恢复**：新增备份页，全量 6 表 + 元信息导出为单个 JSON（Picker 免权限）；恢复前五项校验（结构/表键/版本/行数/逐行字段）+「覆盖当前数据」二次确认，单事务整库替换、失败自动回滚，恢复后账本指针重置。
   - **记账提醒**：新增提醒设置页（开关 + 时间选择，默认 21:30），基于系统代理提醒每日循环触发；提醒 ID 持久化，改时间/关闭先取消旧提醒，异常自动回滚一致态。module.json5 仅新增 `PUBLISH_AGENT_REMINDER` 一项权限（系统授予型，无弹窗），隐私政策与用户协议已同步。

## 关键决策
- 导出修复采用「三态 + 失败点留痕」而非继续静默，让问题可定位。
- 账本删除口径裁决为「无流水可删 + 事务内级联清理 + 二次确认」（原 PRD「仅空账本」口径因预置系统分类实际不可执行）。
