# 轻账本（LifeLedger）上架前测试审查报告

- 审查日期：2026-09-15
- 审查范围：entry/src 全部源码（约 110 个 ArkTS 文件）、AppScope/构建配置、resources 资源与多语言、docs 文档与上架合规
- 审查方式：13 个并行专项审计（配置 / 数据层 / 业务服务 / 安全备份 / 生命周期导航 / 通用与首页组件 / 记账列表图表组件 / 主流程页面 / 设置类页面 / ViewModel / 工具类 / 资源国际化 / 文档合规），全部逐文件精读 + 跨文件交叉验证
- 总体结论：**核心架构扎实**（整数分金额、事务串行化、隐私前置路由、零权限零网络、备份恢复先校验后事务均落实到位），但存在 **4 个必修代码缺陷 + 1 个合规文本缺陷 + 2 个构建阻塞 + 1 个文档口径风险**，修复后方可提审。

## 一、严重问题（上架前必须修复）

### S1. 转账后两个账户余额都不变 —— 核心算账缺陷 ⚠️ 最高优先级
- 位置：`service/TransactionService.ets:106-133`（转账写镜像双行）+ `service/AccountService.ets:186-196、229-252`（余额聚合 SQL）
- 问题：一次转账落库两条镜像流水（A 行 account_id=F/to=T，B 行 account_id=T/to=F），而余额公式 `transferIn - transferOut` 对每个账户恰好各命中一次，**正负抵消，净效应恒为 0**。转账后转出方不减、转入方不增，首页资产卡、账户余额全部失真。
- 修复：聚合口径限定单边出账行（如 `id < related_tx_id`），`getBalance` 与 `getAllBalances` 同步修改，并补「转账后两账户一减一增」回归测试。
- 附带：镜像双行还会在流水列表中显示成两条重复记录（明细观感问题，可一并过滤）。

### S2. 应用锁在子页面完全失效（可绕过）
- 位置：`pages/Index.ets:213-222` + `ability/EntryAbility.ets:96-99`
- 问题：PinLockOverlay 只挂在 Index 主页。用户停留在 router 压栈的子页面（记账页、详情页、**导出页、备份页**）时切后台超 30 秒，回前台后 LOCKED=true 但顶层子页面无任何遮挡，账目可见、可编辑、**甚至可不输 PIN 直接导出 CSV/备份**。两个独立审计交叉确认。
- 修复（三选一或组合）：① 锁定层提升到窗口级；② 每个 @Entry 页面根部挂载响应 LOCKED 的覆盖层；③ 重锁时先 router.back() 收敛到根页再置锁。

### S3. 首页「总资产」大字实际显示的是净资产
- 位置：`components/home/AssetCard.ets:59`
- 问题：标签是「总资产」，渲染的却是 `netAsset`，与下方「净资产」明细重复且数值错误。首页最核心数字误导用户。
- 修复：59 行改为 `this.summary.totalAsset`。

### S4. CSV 导出无公式注入防护（CSV Injection）
- 位置：`service/ExportService.ets:219-229`
- 问题：备注/分类名/账户名原样写入 CSV，以 `=`、`+`、`-`、`@` 开头的字段在 Excel 中会被执行为公式。配合备份恢复可导入他人文件，构成「恶意备份 → 恢复 → 导出 → 打开即外发数据」的第三方攻击链。上架安全检测常见打回项。
- 修复：`joinRow` 对以上字符开头的文本前置单引号 `'`。同文件还有 `\r` 未转义导致错行（:223）一并修。

### S5. 隐私政策缺少开发者/运营主体名称
- 位置：`resources/rawfile/privacy.md:1-8`（全文缺失）
- 问题：全文仅以「本应用」自称，只有客服邮箱。华为审核指南要求隐私政策必须含运营主体名称及联系方式，缺主体是常见拒审项。同文件 :81 还有章节交叉引用错误（「第 8 节」应为「第 9 节」）。
- 修复：补充与 AGC 实名信息一致的主体名称，并与 AGC 托管的隐私声明保持四处一致。

### S6. release 签名配置全部为占位符 —— 出包硬阻塞
- 位置：根目录 `build-profile.json5:21-27`，全部 `REPLACE_WITH_*`
- 修复：在 AGC 申请发布证书与发布 Profile 后填入真实材料（详见上架指导）。

### S7. default 调试签名指向 Windows 路径，本机（macOS）构建必然失败
- 位置：`build-profile.json5:8、11、13`（`C:\Users\33719\.ohos\...`）
- 修复：本机 DevEco Studio → File → Project Structure → Signing Configs 重新生成本机调试签名。

### S8. 调试签名密码硬编码在 build-profile.json5 并已入库
- 位置：`build-profile.json5:10、14`（加密形态），`.gitignore` 挡不住配置文件内嵌密码
- 修复：release 密码绝不可入库；若仓库已推送远端，清理 git 历史并重新生成调试证书。

### S9. 文档口径风险：PRD-v1.1 把「每日记账提醒」列为 P0 必交付，实现未交付且未留痕砍除
- 位置：`docs/PRD-v1.1.md:71、199` 与 `docs/上架打包SOP.md:5` 冲突
- 影响：若审核材料按 PRD 口径宣称提醒功能，直接命中「描述功能未实现」驳回项。
- 修复：PRD-v1.1 变更记录追加「F-10.7 顺延」裁决；ARCHITECTURE-v1.1 的 T04 同步标记。**当前不得在 AGC 申请代理提醒能力、不得在 module.json5 声明相关权限。**

### 接近严重（建议一并修复）

## 二、细节问题汇总（不阻塞上架，建议迭代修复，共约 70 项）

### 数据层（13 项）
- 迁移循环缺 `step.to > current` 守卫（配置错误时启动死循环）
- 全库无外键约束，引用完整性无 DB 层兜底
- 分类种子「有任一系统分类即整体跳过」，部分缺失永不补种
- clearAllData 后 lastAccountId/lastCategoryId 悬空
- `close()` 不重置 readOnlyMode；ll_budget_item 无唯一索引和时间戳
- 数据库 S1 级未加密（建议注释说明取舍）
- 其余：索引冗余、commit 风格不一致、amount 无 CHECK 约束等

### 业务服务（10 项）
- 删除流水不回退分类 use_count（常用置顶逐渐失真）
- 预算「日均可用」对历史/未来月份按今天计算，口径错误
- 净资产口径：非信用卡账户负余额凭空消失（高估净资产）
- 「账期起始日」设置无任何消费方（死设置）
- 搜索 LIKE 未转义 `%`/`_` 通配符
- 余额聚合 SQL 不带 ledger_id 过滤（正确性依赖隐式不变量）
- 「上次账户/分类」记忆为全局值，切账本后残留
- 同日多条流水无二级排序键，顺序不稳定

### 安全与备份（约 15 项有效细节）
- PIN 哈希单轮 sha256 无 KDF 迭代 + 校验无次数限制（4 位 PIN 可在线穷举，建议错误计数提示 + 指数退避）
- onForeground 重锁只查 isLockEnabled 未查 hasPin（统一用 AppLockService.isEnabled）
- pinHash/pinSalt 被读入 ViewModel 在 UI 层流转（只应回传布尔）
- 备份选择器无类型过滤；「文件过大」与「文件损坏」共用同一错误文案
- 诊断报告 appVersion 硬编码 '1.0.0'（AboutPage 已是动态读取，应对齐）
- LogUtil 无 release/debug 分级开关；TextEncoder.encodeInto 在 API 12 起 deprecated
- PermissionGuard 运行时自检恒通过（虚假合规保证，应进 CI 脚本）

### 生命周期与导航（5 项）
- 「＋」按钮无防重入，快速连点压入多个记账页；pushUrl 失败静默
- 状态栏避让高度仅冷启动记录一次，折叠屏/分屏后不更新
- ThemeStore.apply 无条件刷新状态栏（冗余调用）
- DB 初始化失败容器层无全局兜底标志

### UI 组件（约 20 项代表性）
- AmountText 超大金额无省略号防溢出
- ConfirmDialog/InputDialog 无取消回调；确认按钮无防连点守卫
- InputDialog 复用时可能残留旧文本
- NavTitleBar 返回热区仅 32vp（建议 ≥40vp）
- SettingItem 分割线缩进与无图标布局错位；Toggle 单向绑定依赖父级回写
- LedgerSwitcher 账本列表加载失败仍打开空半模态
- MonthSummaryCard 单边为 0 时比例条残留 1% 色条
- RecentListCard 卡头缺 SpaceBetween，「查看全部」未右对齐
- BarChart 数据清空时残留最后一帧（clearRect 顺序问题）
- 流水副行时间恒显示 "00:00"（txDate 恒为零点，建议移除或存真实时间）
- SearchBar 点 × 清空仍走 300ms 防抖
- AccountSelector 转账场景 sheet 标题不随 labelRes 变化

### 页面（约 20 项代表性）
- RecordEditPage 的 mode/categoryId/monthKey 是死参数，注释失实
- 编辑模式不做选中项失效兜底（悬空 id 穿过页面校验，保存时才报错）
- HomePage 三处 pushUrl 未 .catch，与同文件写法不一致
- 重复选择当前账本仍触发全站重载
- CategoryTxListPage 返回时 @Watch 与 onPageShow 双触发两次全量查询
- 预算/账户期初金额输入框用 InputType.Number，**无法输入小数**（建议改 NUMBER_DECIMAL）
- 归档开关失败时 Toast 后列表不复位
- MinePage 任何设置变更返回都闪骨架屏
- 「导出诊断信息」入口上架版建议隐藏（挪到关于页连点唤出）
- ExportPage 失败弹窗硬编码中文，未走资源

### ViewModel（23 项代表性）
- TxDisplayMapper 注释承诺的分类缺失兜底「其他」未实现（空白显示）
- BackupViewModel catch 内 `err.message.length` 对非 Error 抛值二次抛异常
- 统计页趋势口径不随浏览月份移动（恒为近 6 个月）
- RecordEditViewModel 三个键盘表达式方法是死代码且口径与主链路不一致
- clearAllData 不清理 SettingsService 残留键

### 工具类（8 项）
- DateUtil.addDays 固定 86400000ms 加法，跨夏令时偏 1 小时（当前无调用方，死代码隐患）
- monthKeyToStart 非法键静默回退当前月
- MoneyUtil 两条解析链路对第 3 位小数舍入语义不一致
- ExpressionEvaluator 无安全整数兜底（可输入注定被拒绝的超大表达式）
- LazyDataSource.getData 无边界检查（瞬时崩溃窗口）

### 资源与多语言（5 项）
- string.json 内嵌的旧版隐私政策/协议正文是死资源且已分叉（含「最终解释权」高风险表述，建议删除）
- AppScope 无 en_US 资源，英文 locale 桌面图标名恒为「轻账本」
- start_window_background 固定纯白，深色模式启动闪白（建议加 dark 限定资源）

### 文档同步（10 项，提审前收口）
- ARCHITECTURE.md 的 AR-1（ready 门）未按文档实现，二选一统一
- PRD 包名占位符 `com.<devname>.lifeledger` 未回填实际包名（误抄到 AGC 会拒收）
- targetSdkVersion 文档定稿 26.0.0 与实际 6.0.0(20) 不符，SOP 需补记
- 页面数量口径过期（21 → 实际 24）
- module.json5 建议显式加 `"requestPermissions": []` 自证零权限（文档 D10 宣称的形态）
- 提审前建议 clean build，避免 .preview 旧缓存误打包

- 隐私前置：未同意不初始化数据库、返回拦截、真实退出，合规链路完整
