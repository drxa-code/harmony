- 根因（NEXT/API20 确定坑）：`FileUtil.copyToUri` 用 `fileIo.openSync(uri, WRITE_ONLY|CREATE|TRUNC)` 打开 DocumentViewPicker 授权 URI，在 NEXT 上被拒（典型 `13900001 Operation not permitted`），必须用 `READ_WRITE` 才能写 picker 授权 URI
- 修复：`copyToUri` 改 `READ_WRITE|CREATE|TRUNC` 优先打开，失败回退 `WRITE_ONLY|CREATE|TRUNC`（直接传枚举位运算，异常自然冒泡到 ExportService 的 copy catch）；用 `destFd:number` 持有描述符，避免 `fileIo.File|null` 类型与 throw 变量（触发 arkts-limited-throw）
- 全链路诊断加固（防再盲修）：`ExportOutcome` 加 `detail` 字段；`ExportService`/`BackupService` 四处 catch 填 `BusinessError.code + ':' + message`；`Result<T>` 加可选 `detail`；`MineViewModel` 透传；`ExportPage` 失败时改 `AlertDialog` 显示完整错误码（含 code），不再只 Toast 中文分类
- 编译坑：首版 copyToUri 多策略用 `modes:number[]` + `as fileIo.OpenMode`（10505001：OpenMode 当类型非法）+ `throw lastErr`（10605087：arkts-limited-throw 拒绝 throw 可能为 null 的变量）→ 2 个 ArkTS ERROR；改简化回退版后 CompileArkTS 0 ERROR
- 验证：增量 assembleHap → CompileArkTS 0 ERROR；手动 app_packing_tool.jar → HAP 1.96MB 成功
- 真机待验：① 备份/CSV 导出应正常落盘；② 若仍失败，AlertDialog 会显示精确 `code:message`，直接贴回即可定位
